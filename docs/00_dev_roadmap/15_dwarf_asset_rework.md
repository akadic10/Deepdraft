# 15 - Dwarf Asset Rework

## Purpose

Lock the revised dwarf visual contract before regenerating GLB assets. The current generated files drift from the design in `docs/40_economy_colony/41_dwarf_agents.md` and `docs/40_economy_colony/41b_dwarf_appearance_glb.md`: the body mesh includes arms and legs, while the intended dwarf silhouette is an oversized head, compact torso, detached hands, and detached feet.

## Reference Audit

Stonehearth hearthlings are useful as a modularity reference, not as an anatomy target:

- Default hearthlings compose separate `head.qb`, `body.qb`, and `eyes.qb` models.
- Hair, eyebrows, and facial hair are customization models.
- Skin, hair, and eye colors are material maps, not duplicate geometry files.
- Stonehearth bodies include limbs, but those limbs are named matrices supported by a skeleton. Deepdraft dwarves should keep the modular discipline while preserving the no-arms/no-legs silhouette.
- Stonehearth's hair layering for headgear compatibility is worth carrying forward. A future pass can split hair into headgear-safe layers if equipment clipping becomes a problem.

## Current Deepdraft Problems

- `tools/generate_dwarf_glb.py` currently builds `body_base.glb` as torso plus arms plus legs.
- `body_base.glb` duplicates appendage mass even though `hand.glb` and `foot.glb` exist as separate parts.
- Hands and feet are authored as appendage ends instead of clearly detached floating forms.
- Skin-bearing hands and feet should tint with the selected skin tone, not behave as fixed-color props.
- Asset scale guidance is inconsistent: the art guide says character/item imports should use `0.125`, while the generator reminder still says `0.0625`, and existing `.glb.import` files currently show root scale `1.0`.

## Target Contract

- `body_base.glb` is compact torso plus short neck only.
- `body_base.glb` must not include arms, legs, pelvis columns, shoulder-arm extensions, connector tubes, or ankle/wrist geometry.
- `hand.glb` is one floating mitten/block hand authored in the shared frame and mirrored at runtime for left/right.
- `foot.glb` is one floating foot or boot authored in the shared frame and mirrored at runtime for left/right.
- `head_[age].glb` remains the dominant silhouette piece.
- The visible dwarf target remains about 3.3 blocks tall, while gameplay/logical height remains the 3-block agent described in `41_dwarf_agents.md`.
- Skin-bearing meshes are tint-compatible: head, body, hands, and feet.
- Hair, beard, and brows stay neutral/tint-compatible. Future headgear-safe hair layers should preserve the same registry pattern.

## Regen Phases

1. Document the contract in this roadmap note and `41b_dwarf_appearance_glb.md`.
2. Update `tools/generate_dwarf_glb.py` to generate the corrected torso, detached hands, and detached feet into a temporary output folder first.
3. Render or inspect an assembled neutral dwarf preview before replacing project GLBs.
4. Regenerate the full dwarf GLB set after the base anatomy reads correctly.
5. Validate Godot import scale and in-world height through project settings or reimport workflow; do not hand-edit `.import` files.

## QA Checklist

- No arm or leg voxels exist in `body_base.glb`.
- Body bounds are compact relative to the head.
- Assembled silhouette reads as oversized head, squat torso, detached hands, detached feet.
- Hands and feet accept the same skin tint as the head/body.
- Import scale and actual in-world height match the 3.3-block visual target.
- No manual edits are made to generated `.import` metadata.

## Status

- Phase 1 complete: contract is documented here and in `41b_dwarf_appearance_glb.md`.
- Phase 2 complete: `tools/generate_dwarf_glb.py` now emits torso-only body geometry, detached tint-compatible hands/feet, and the corrected `0.125` import scale reminder.
- Phase 3 complete: visual QA renders were generated at `tmp/dwarf_visual_qa/`.
- Phase 4 complete: live GLBs were regenerated in `assets/dwarves/`; only `body_base.glb`, `hand.glb`, and `foot.glb` changed because the remaining files regenerated byte-identical.
- Phase 5 complete: Godot reimport preserves dwarf `.glb.import` Root Scale = `1.0`, so the generator now bakes the `0.125` character scale into exported GLB positions. Generated dwarf GLBs should remain at Godot Root Scale = `1.0`.
