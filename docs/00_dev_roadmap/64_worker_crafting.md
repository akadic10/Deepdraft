## Playable first workshop

Any dwarf whose current profession is **Worker** can make the colony's first
workbench and torches. No Carpenter promotion is involved. The new **Craft**
dock button opens Worker crafting; selecting an installed Crude Workbench also
offers **Craft items** in Object explorer.

| Recipe | Input per batch | Output | Work | Workshop |
|---|---|---|---|---|
| Crude workbench | 1 allowed log (Pine default) | 1 packed bench | 8 simulation seconds | None; made on clear ground |
| Wooden torch | 1 allowed log (Pine default) | 4 packed torches | 6 simulation seconds | Installed crude workbench |

**Stump redesign:** the Crude Workbench is now one bark-covered trunk section,
with a rough axe-cut end, split marks, an uneven rim and a slightly flared base.
It has no trestles, pegs or fitted planks. Its 1×1 footprint replaces the original
2×1 bench; the central working surface is 0.875 blocks high and the tallest
remaining splinter is 1 block high. It uses the existing timber palette, eight
voxels/block and baked 0.125 export scale. The placed model and catalog thumbnail
are regenerated by `generate_worker_crafting.py --only bench` and
`FurnitureCatalogThumbnails.gd -- --only=crude_workbench`.

All four cardinal sides are valid work positions regardless of furniture
rotation. After collecting the ingredient, the Worker reselects the nearest
walkable side of the claimed stump, places the material on its near edge and
faces inward. Walls may block individual sides; one open side is sufficient.
Only one Worker uses a stump at a time. Item, furniture and recipe keys stay the
same, so old packed items/orders still work. Existing saved benches become stumps
at their original placement cell; shrinking the footprint releases the extra
tile rather than occupying new space.

Start with a Pine log from a felled tree, or choose another allowed species.
Queue a bench, then install the finished
item using **Place → Workshops** (or **Place finished item** in Craft). Queue
torches and mount them using **Place → Lighting**. Workers collect actual loose
or stored timber, carry it, visibly shape it, and leave packed outputs for normal
hauling and placement. A batch consumes its timber only at the final set-down.

First-workbench crafting uses the dwarf's walkable pickup position, so distant
timber is shaped where it was collected. An earlier implementation retained the
worker's position at assignment and caused an unnecessary return trip, often to
the settlement flag. The flag has no crafting role. Recipes requiring a workshop
still carry timber to that workshop. The inspector reads the order's current
work position instead of the scheduler lease's placeholder `(0,0,0)` target.

Both recipes reuse the Worker's axe animation and the existing six-variant
axe-on-wood sound bank. One positional hit plays when the axe crosses contact
(0.54 of its 1.15-second cycle), at the top of the physical log. Contact holds
do not repeat it; long frames coalesce missed strikes into one hit. Saved work
progress also drives sound timing, so resuming never replays earlier strikes.
Clock speed changes cadence, not pitch. Pause, cancellation, hidden Workers
and sliced-away work suppress new hits; short existing tails finish normally.
The shared Work bus supplies camera-distance/zoom attenuation, stereo placement,
sample variation and voice limits. Crafting adds no tree-felling completion sound.

Recipes accept raw timber through the `timber` material tag, but each order has
an explicit allowed-wood list. **Only Pine is selected by default.** Players can
opt into Juniper, Oak or Apple from the recipe's **Allowed wood** checklist or
change an existing order's **Wood** menu. Running out of selected wood leaves
the order waiting; excluded species are never substituted. Oak staves and
finished wooden furniture do not qualify. The existing iron-bracket Wall Torch remains
a separate item; the Worker-made Wooden Torch has a wooden fork and peg.

Workers choose the nearest unreserved loose log among allowed species first.
If none is loose, they choose the nearest available stored unit across allowed
species, ground stockpiles and containers. Distance uses the existing Manhattan
grid metric. The checklist is not a species priority list; alphabetical order
does not override distance. Suspended containers and failed withdrawals do not
block other allowed storage.

Wooden torches use the existing animated flame, room heat, underground lighting
and wall-support pipeline. Their base mounts **1.5 blocks above the floor**, so
the 1.5-block model fits three-block-high starter tunnels. Light range is 6,
energy 1.3 and heat 150. Packed torches are unlit. Like the existing lights,
installed torches remain lit without fuel or burn-out.

## Menu and orders

The cabinet uses shared charcoal/copper chrome, placed-model recipe thumbnails,
a parchment recipe card and stable order rows. Ingredient availability, workshop
requirements, yield, work time and finished stock are visible. **Make batches**
queues a finite number of batches; **Keep in stock** sets a spare-item target.
Maintain orders replenish in full batches, so the final batch can exceed a
non-multiple target. Installed, reserved and currently carried goods do not count
as available spares. A duplicate maintain order updates the existing target and
allowed-wood list.

Each recipe keeps its own draft wood choice while the menu is open; queued
orders store independent copies. The menu shows available counts by species.
Clearing all choices disables new orders and leaves an existing order waiting
for a wood choice. Changing an active order to exclude its current log returns
that log and preserves the order's partial work.

Orders support pause/resume, cancellation and moving unassigned orders earlier
or later. Rows report missing timber, missing/free workbench, worker/route waits,
work progress and met stock targets. Completed finite orders disappear. Waiting
orders do not fabricate materials or a workshop. **Place finished item** selects
that output in the existing placement catalog. Its Crafting count includes finite
requests and the batches needed to meet maintain targets.

The dock now has eight entries: Orders, Zones, Rooms, Place, Craft, Colony,
Inventory and Menu. Craft closes active drawing/placement modes; switching to
another dock group or pressing Escape closes Craft. The compact layout keeps
the queue and primary action visible. World clicks remain blocked under the UI.

## Ownership and interruption

- `CraftingManager` is a scene-owned system in `debug_world.tscn` and the single
  loader of `data/workshops/worker_crafting.json`. It owns persistent player
  orders, transient workbench claims and one scheduler lease per active order.
- `WorkerCraftOrder` implements the existing fetch work-source contract. The
  `CRAFT` task type is appended to the enum, with priority 46: after mining and
  felling, before placement and hauling. Workers finish their current job before
  selecting another; queueing crafting does not preempt mining.
- `DwarfAgent` reuses physical pickup/carry/set-down and a shaping pose based on
  the existing axe rig. Cargo is aligned with the real tabletop and item bounds.
  The inspector/roster reports Crafting rather than Placing furniture.
- One dwarf claims a bench while collecting and working. Different orders cannot
  use it concurrently. Multiple benches can service different orders; one order
  does not fan out into parallel batches.
- Cancellation, sleep, pause, invalid navigation and bench removal release
  claims and return carried timber. Partial work belongs to the order. Pausing
  or sleeping preserves it; cancelling intentionally removes the order.
- Save section `worker_crafting` stores recipe keys, batch/stock quantities,
  mode, pause state, work progress and `allowed_ingredients`. Worker, task, item
  and bench reservations are rebuilt after load, never serialized. Carried timber
  is saved by the existing dwarf cargo owner and restored as loose goods. Older saves without
  this section start with an empty queue. Orders saved before the wood selector
  adopt the recipe's Pine default. Explicit empty or invalid saved lists stay
  empty rather than silently allowing other species.

This first executor intentionally supports one physical timber unit per batch.
Multiple ingredients, fuel, profession progression, quality and specialised
workshops remain future systems. No new autoload or global script class was added;
restart play mode to use the feature.

## Stonehearth references

Read the installed `stonehearth.smod` archive as reference, without modifying it:

- `stonehearth/jobs/carpenter/recipes/carpenter_workbench_recipe.json` uses one
  wood resource and has no workshop requirement. Deepdraft borrows that bootstrap
  pattern for Workers.
- `stonehearth/ui/game/show_workshop/show_team_workshop.html` presents recipes,
  ingredients, orders and make/maintain choices, matching the supplied screenshots.
- `stonehearth/ai/actions/produce_crafted_items.lua` commits ingredients and outputs
  on completion; Deepdraft retains its own physical-cargo ownership implementation.

All new models, UI and gameplay code are authored for Deepdraft. The reproducible
art generator is `tools/generate_worker_crafting.py`; thumbnails are native renders
of the actual models using `FurnitureCatalogThumbnails.gd -- --only=crude_workbench,wooden_torch`.
