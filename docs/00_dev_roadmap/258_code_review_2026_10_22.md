# 258 — Code review for poor practices (2026-10-22)

**Status:** all eight steps done (2026-10-22). **Player impact:** step 1 fixes; step 2 removes the lighting toggle and storage-furniture code (none was in use).

The owner asked for a review of the GDScript and JSON for bad practices, after deleting
`data/content_retirements.json` (a save migration for development saves nobody has).
- **How it was done:**
  - five read-only reviewers, one each for saves and legacy code, world and rendering,
    tasks/dwarves/furniture, UI and registries, and JSON data;
  - a grep scan.
- **Scale:** about 54,000 lines of game GDScript and 107 JSON files.
- Every finding was checked against the code. The ones marked ✔ were also re-checked
  first-hand.

## Step 2 — done

Saves now have exactly one format. `SaveSnapshotValidator` describes only schema 2, and a
save with any other `schema_version` is rejected with "start a new world".
- **Deleted save compatibility:**
  - `TerrainSaveMigration.gd`, the dual-schema validator, `InteriorTracker`'s
    `legacy_mined` branch and `SaveFileStore`'s water-terrain branch;
  - furniture `layout_version` / `legacy_layouts` (code, validator and the two JSON files);
  - the wildlife deer/wolf fallbacks, the stockpile `filter_tags` duplicate and the
    accept-all filter default;
  - the old-save chair tiebreak, the "pre-filter" crafting default, the ladder
    "shortened tails" rounding and the camera fixed-step zoom fallback (with its JSON keys);
  - the pine `spawn_chance` alias (now `base_density` like the other trees).
- **Now required:** fields that are always written are no longer optional, and their
  restorers read them directly: `total_blocks`, ghost `required_material_id`, installed
  `material_id`, `food.last_dining` and every mood field except
  `solo_recreation_memory_hours`.
- **Furniture storage containers deleted** (owner decision):
  - removed `ContainerStorageComponent` and every hook in `StockpileManager`,
    `FurniturePlacementController`, `InstalledFurnitureComponent`, `FurnitureMoves`,
    `ItemDropManager`, the object explorer, `DockUI` and the storage inspector;
  - the save fields `inventory`, `instances` and `storage_filter` are gone;
  - `StorageItemLayout` stays, because the construction-materials crate uses it.
- **Lighting toggle removed** (owner decision): the main world always uses Hearthblock
  lighting; other scenes keep their own environment.
  - Removed the switch, the authored-look snapshot and restore, the dock entry, the
    `enabled` key and `FurnitureLighting.apply_look`.
- **Tools deleted:** `CopiedSaveReview.gd` (loaded copied old saves and patched their
  layouts), `HearthblockLightingReview.gd` + `RunLightingReview.ps1` (on/off comparison)
  and `ShaderSlotReview.gd` + `RunShaderSlots.ps1` (built on `CopiedSaveReview`).
- **Tests:**
  - deleted `TestStorageFixture`;
  - about 25 tests that used containers as storage fixtures now use stockpile zones, or
    lost their container-only cases;
  - old-save cases removed;
  - `SaveWorkerChecks` now checks that another version is rejected, instead of comparing
    against a frozen old validator;
  - `SaveManagerRoundTripTest` rejects 227 malformed snapshots, including each newly
    required field.
- **Results:** the gate is 50/50. Across the full suite (166 tests) everything passes
  except four known failures: `CaveGenerationTest`, `DwarfInspectorTest` (uses the
  retired `wooden_table`), `ToolPromotionTest` (now fails on its sealed-kit route check
  rather than timing out) and `EnvironmentDetailsTest`.
  - `BoulderPilotTest` and `FurniturePlaceTest`, which were failing before, now pass.
- **Not done:** rejecting saves that name content the game no longer defines. Startup
  resume validates before the scene's content owners exist, so this needs furniture, item,
  recipe and flora definitions in autoload registries (step 6). Until then, unknown keys
  are still skipped on restore.
- **Noticed, unchanged:** a construction crate whose cell later becomes part of a
  stockpile is restored on a different cell.

## Step 5 — done

`tools/lint_project.py` is a Python text scan that takes under a second. The runner runs
it with the gate and `-All`, and a lint failure fails the run. It checks game scripts
(`scripts/` without `scripts/tests/`) and data:

| Rule | Catches | Known today |
|---|---|---|
| `private-access` | `x._member` or `call("_member")` on another object | 626 in 68 files |
| `json-owner` | `res://data` paths outside `registries/` and `systems/`, a data path read by two scripts, and file reads outside those folders (save files and window layout allowed) | 0 |
| `dev-gate` | DEV buttons in a script that never checks `dev_tools_enabled` (the Job inspector panel is allowed, since it lives in a gated window), and DEV dock entries outside a `dev` menu | 0 |
| `garbled-text` | the cp1252 mojibake signatures in scripts, data, docs, tools and scenes | 0 |
| `unused-data` | data JSON files nothing names or scans, and keys no script or tool mentions (`data/art` keys and id maps skipped) | 149 in 52 files |
| `legacy-code` | legacy, backward compat, compat, migrate/migrated/migrating | 11 in 9 files |
| `world-literal` | 1024, 1023 or 127 typed in code instead of the WorldData constants | 79 in 33 files |
| `file-length` | scripts over 1,500 lines may not grow | 6 files |

- **The baseline:** `tools/lint_baseline.json` holds the known violations, counted per
  file and key (such as `TaskManager._agents`), so moving lines doesn't matter.
  - `--update-baseline` only lowers counts, after a fix.
  - `--reset-baseline` rewrites the file and needs the owner's approval.
- **Checked:** a probe script containing one violation of six of the rules failed with
  all six reported; the clean tree passes. The gate is 51/51 with lint OK.
- **Not done:** Godot's own GDScript warnings would need a `project.godot` change. They
  are skipped until step 8 shrinks the large files.
- **Limits:**
  - Unused-key detection is a word match, so keys built from strings (for example
    `"%s_body" % sex`) can look unused. Those are in the baseline.
  - The private-access count includes legitimate same-class access, such as a component
    reading its own owner's fields. Step 6 works through it.

## Step 6 — done

Eight parts, run as four batches with the full suite after each. Lint known violations
went from 865 to 439.

1. **One work-source table.**
   - `scripts/components/WorkSourceTable.gd` replaces the bookkeeping copied in
     `LadderSystem`, `BridgeSystem`, `SurfaceFloraSpawner`, `SurfaceDetailManager` and
     `FurniturePlacementController` (ghost and installed work).
   - A release reaches only `work_task_released` and never "gone", which was the ladder
     bug.
   - Retiring forgets the source before cancelling, so a cancel can't re-post work.
   - The work-journal key uses `Task.type_name()` instead of the enum number.
   - Test: `WorkSourceTableTest`. It caught the bug when the release routing was broken on
     purpose.
2. **`ContentRegistry` autoload** (needs one project reload).
   - It holds the furniture, item, recipe and tree definitions, loaded before
     `SaveManager`.
   - Scene systems take deep copies.
   - Saves naming unknown furniture, items, recipes, tree species or stages, or planted
     bushes, now fail validation, including at startup resume. The restore-time skip
     branches are gone.
   - The Registry Pattern section of `CLAUDE.md` is rewritten for this.
   - Tests: `ContentRegistryTest`, plus 10 unknown-content cases in
     `SaveManagerRoundTripTest`.
3. **Public accessors.** Private access went from 626 to 273.
   - New public APIs include:
     - `TaskManager.get_agent`/`get_agents`;
     - `WorldGenerator.is_maps_ready` and a `maps_ready` signal;
     - WorldRenderer methods for `XrayController`;
     - read-only `DwarfAgent` getters;
     - furniture lookups (`get_installed`, `get_ghost`, `get_installed_pieces`…);
     - `NavGrid`/`BlockRegistry` key and ladder lookups.
   - The 273 left are components and helpers reading their own owner (198 of them are
     DwarfAgent's components).
4. **Duplicated logic merged:**
   - The removed-terrain record and the visible-surface rule now live in `WorldData`
     (`is_removed_terrain`, `visible_top_y`). The mined-block sets in
     `MiningDesignationController` and `WorldRenderer` are gone.
   - Terrain rays all use `ObjectPicking.terrain_hit`; height-field marches use the new
     `surface_hit`.
   - Task categories are constants in `Task.gd` (`SURFACE_WORK`, `GATHER_WORK`,
     `SHRUB_WORK`, `COMMON_WORK`).
   - Test: `TerrainPickingTest`.
   - The copies differed in a few edge cases, and the most correct behaviour was kept:
     - a block rebuilt and then mined again counts as removed at once;
     - surface marches stop below the world floor;
     - camera zoom no longer "hits" at y −1 off the map edge.
5. **World-size literals:** 79 down to 6.
   - New dependency-free `scripts/systems/WorldSize.gd`, which `WorldData` aliases, so
     the save validator and the layout scripts compile in `--script` tests.
   - `WorldData.MAX_Y` / `SliceController.MAX_SLICE_Y` replace 127.
   - The 6 that remain aren't world sizes (table sizes, a hash mask, macro-cell areas).
6. **DockUI is no longer a service locator.**
   - `TreeFellingController` gets the mining controller through `mining_path`.
   - `CraftingManager`, `WorldEventDirector` and `DwarfDirector` get the dock through
     `dock_ui_path` exports, set in `debug_world.tscn`.
   - The `command_dock` group stays only so tests can find the dock.
7. **Item manager access is typed:**
   - `ItemDropManager.find(tree)` replaces 40 group lookups;
   - about 72 string `.call()`, `has_method` and string-connect sites became direct
     typed calls;
   - `drop_manager` fields are typed `ItemDropManager`.
8. **JSON loaders report errors.**
   - `scripts/registries/JsonData.gd` (`read`, `read_dict`, `read_array`, `inspect`)
     reports a missing file, a parse error (with a 1-based line number) or the wrong
     shape, always with the path.
   - About 25 loaders use it; silent loaders and warnings became errors, and defaults
     still apply.
   - Only the user-data window layout stays quiet when missing.
   - Test: `JsonDataTest`.

- **Results:**
  - The gate is 55/55 with lint OK.
  - The full suite is 167/171, failing only on the four known tests.
  - `WorldResourceDiagnosticsTest` got a 300 s timeout, because it ran close to 180 s

- **Results:**
  - No game script is over 1,500 lines any more, so the lint `file-length` baseline is
    empty. The largest are `SurfaceFloraSpawner` (1,372) and `TerrainTileMesher` (1,305).
  - Lint known violations went from 340 to 264.
  - A temporary comparison against a frozen copy of the old generator, on four seeds and
    160,200 samples per seed, found zero differences.
  - Scheduling code was moved mechanically, so order and tie-breaks are the same.
  - The DEV switch still hides DEV Mine, Instant Build, Remove and the block inspector.
  - The gate is 55/55. The full suite is 167/171, failing only on the four known tests.
- **Block lookup speed:** right after the split, block-id lookups in `WorldBlockFill`
  measured 11–18% slower than the old generator.
  - **Fix (owner request):** the helper now holds direct references to the cave columns,
    the gem/soil/domain noise and the lake/tarn/bank dictionaries. The generator's setters
    for `_cave_layout` and the noise fields call `bind_layers()`, and its `_init` binds
    once, so nothing can go stale.
  - **What stays a live read:** the packed maps and `world_seed`. Tests edit them in place
    through the generator, and caching a packed array would copy-on-write away from those
    edits.
  - **Measured:** 200,000 lookups on seed 1234 took 1,154 ms before the fix and 1,086 ms
    after, with an identical result digest.
  - **The rest of the gap:** caching `heightmap` too saved only about 1% more, so the
    named reads were not the main cost. The old generator copy used for the 11–18% figure
    is gone, so the rest can't be compared directly.
- **Dead code removed along the way:** `_rebuild_all_zone_overlays`, `_build_line_mesh`,
  `_append_block_lines`, `_sort_v3i` and `_yaw_dir`.
